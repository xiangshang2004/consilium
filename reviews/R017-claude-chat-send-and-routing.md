# R017：在 App 里直接发消息、自动分配、偏好学习、按额度交接（Claude，2026-11-20）

## 设计目标（2026-11-20）

- 支持在 Consilium 界面中直接发起消息，不必先去桌面端开新对话再手动粘贴；
- 简化交互逻辑与前端界面，做到类似桌面对话客户端的极简体验；
- 支持自动识别意图、分派最合适的接入端，并在日常使用中逐步沉淀稳定偏好；
- 支持各端根据剩余配额与负载相互交接任务，切号仍由用户手动控制；
- 仅面向 macOS 桌面端使用，不强制配置后台自启。

## 做了什么

- **后端**：
  - 允许“使用者”当协调者，只有界面能这样创建，MCP 仍只接受三端。
  - 任务新增 `origin` 字段，标明是否由使用者发起。
  - 新增两张表：`user_messages` 存你说的原话，`preferences` 存学到的偏好（自动去重，最多 30 条有效）。
  - 新增 `handoff_task`：把任务连同进度交给另一端，旧的 `attempt_id` 随即失效。
  - 发给使用者的事件直接标为已确认，不响铃。
- **MCP**：新增 `consilium_preferences`、`consilium_learn_preference`、`consilium_handoff_task`，工具总数 14。自动分配时先选协调者：优先待命中的、其次余量充足的，余量已耗尽的不选。交给协调者的说明以你的原话开头。
- **接口**：
  - 新增 `POST /api/conversations`（新建会诊并发消息）、`POST /api/missions/<id>/message`（在会诊里继续发）、`POST /api/preferences/<id>/delete`（删偏好）。
  - 都沿用 cookie 会话、精确 Origin、JSON 和 CSRF 校验。
  - `/api/state` 新增 `preferences`。
- **前端**：改成 Claude 式布局：左侧会话列表加“＋ 新会诊”，中间是对话（你的话在右侧气泡，各端回复在左侧，处理中显示一行进度），底部输入框可选“自动”或点名。三端状态胶囊栏、进度条、技术徽章都不在主界面显示；主题和各面板收进“⋯”。新增“偏好”面板。只做电脑端。
- **技能**：`SKILL.md` 第 3 节写明界面消息、自动协调、偏好学习和额度交接的做法，并已同步到 Claude Code 和 Codex。

## 验证

- 测试共 93 项，全部通过，`openspec validate --strict` 通过。新增 `tests/test_r017_regressions.py` 6 项，覆盖：直接发、自动分配、追问、偏好、交接、HTTP 防护。
- 旧版式的两条断言（固定只显示 6 条事件、进度条写法）随用户要求的新界面撤掉。安全相关断言全部保留。
- 在隔离的 daemon 上，用内置浏览器实际操作：点名 Codex 发送，替身回复出现在对话里；改选“自动”追问，交给了待命中的 Claude。

- App 重新构建，冒烟测试两种情况都通过，已替换“应用程序”里的副本；技能已重新同步，MCP 配置未变。

## 边界

- 三端只有在待命时才会立刻收到消息；否则弹通知，由用户点开对应 App。
- “学习”指的是可见、可删除的偏好条目，Consilium 本身不训练模型。
- 余量来自 Cockpit 和本地记录，可能滞后；数据过旧时视为未知。切换账号始终由用户手动完成。
