### 2.2 R012 两个 P1

- **P1-1 轮换失败的报告泄露令牌：已修。**
  - 回滚说明只写受保护备份的路径，不再嵌入旧条目原文。
  - 报告、错误信息、汇总都经过 `_redact_secrets` 处理，遮盖 Bearer、JSON 和 TOML 里的 Authorization，以及显式传入的新旧令牌。
  - `claude mcp add` 在创建进程时就抛异常，也会走回滚。
  - 报告新增 `failed_target_may_be_modified` 和 `codex_scope="managed_block_only"` 两个字段，写明了失败目标可能已被改动，以及轮换只覆盖 Codex 托管块。
- **P1-2 并发轮换时认证版本丢失：已修。**
  - `_check_security` 会返回认证时用的 `auth_token_ver`。
  - 签票据时用这个版本，签完再核对当前版本，不一致就作废刚签的票据，返回 401。兑换票据时也按当前版本校验，所以旧版本的票据换不到 cookie。
  - SSE 绑定这个版本；发响应头前、发首帧前，以及循环里的每一步，都会调用 `_stream_still_authorized()` 复查。

## 3. 遗留

| 级别 | 事项 | 说明 |
|---|---|---|
| P2 | 启动时重建 `.seq` 不发脉冲 | `wakeup.py` 里 `rebuild_all_peer_seqs` 仍是 `pulse=False`。会合目录整体被清理后重启 daemon，已经阻塞的 waiter 如果只有积压、没有新写入，就不会被叫醒。这一项 R012 提过，我上次交接的第 8 项也列了。修法：重建时如果 `queued_tasks` 或 `unacked` 大于 0，就发一次脉冲。 |
| P2 | 安装器第二阶段不是整批回滚 | 本轮补了异常回滚和状态如实上报，但多个目标仍是串行改写、失败后不整批撤回。这一项在阶段 4（真实安装）之前修完即可，现在只需在 tasks.md 里记一条。 |
| P3-1 | 一次性票据 `/ui/auth?ticket=` 仍在 URL 里 | 设计如此（30 秒、只能用一次、`Referrer-Policy: no-referrer`），可以接受。做菜单栏 App 时改成 App 内部直接写 cookie，就不用再经过 URL。 |
| P3-2 | 回退套接字目录太长时，报错不够清楚 | `AF_UNIX path too long` 看不出是哪个配置引起的。启动时检查路径长度，报错里写明 `CONSILIUM_SOCKET_FALLBACK_DIR` 太长，并建议改用短路径。 |

## 4. 截图意见（2026-11-20）

**桌面宽度（1440）**：整体干净，像桌面聊天应用；三端胶囊、“演示数据”和“账号未知”的标注、“建议档位”“最后上报于 X 秒前”的写法都照实。小意见：

- “冷通知 · dry-run”是演示模式下的标记，正式模式下不应再出现 dry-run 字样。请确认正式模式下文案会变。

**手机宽度（390）**：

- 顶部占了大约 400 px（标题、主题切换、5 个标签加退出、两行胶囊），底部输入区又占了大约 280 px，844 高的屏幕上，消息只剩大约 1/5 的高度。建议窄屏时：
  - 主题切换和 5 个标签收进右上角一个“⋯”菜单；
  - 胶囊压成一行，可以横向滚动或只显示圆点加百分比；
  - 输入区收起时只留一行，聚焦后再展开快捷按钮。
- 改完后截一张 390 宽、消息较多时的图，确认一屏至少能看到 2 条完整消息。
