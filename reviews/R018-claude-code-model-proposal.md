# R018：照 Claude Code 桌面版的逻辑重做“文件夹、会话、命名”（已实现）

- **作者**：Claude，2026-11-20
- **需求背景**：按桌面对话应用（参考 Claude Code Desktop）的使用直觉重做工作区选择、会话绑定与标题命名，取消容易出错的路径推断。
- **依据**：
  - 官方文档 code.claude.com/docs/en/desktop、desktop-quickstart、worktrees，2026-11-20 查阅；
  - 桌面版会话的典型习惯：每个会话固定一个工作目录；从最近使用的目录（如 `workspace`、`project-a`、`project-b`）或目录选择器选定；支持自定义清晰标题与管理会话派生子会话。

## 一、Claude Code 是怎么做的

| 环节 | Claude Code 桌面版 |
|---|---|
| 开始 | 发第一条消息之前，输入框下面一行控件：环境、**项目文件夹**、权限模式、模型 |
| 文件夹 | 从最近用过的文件夹或预设里选，或者用“Open folder…”调出系统的选择窗口；会话开始后文件夹固定，只能再“添加文件夹” |
| 工作树 | 默认关闭，只有 Git 仓库才出现这个选项；开始前打开；有分支前缀；归档后保留约 30 天 |
| 命名 | 自动起名；点标题栏里的标题可以改名 |
| 侧边栏 | 默认按文件夹分组；不想看的会话归档；会话做完时发系统通知 |
| 多会话 | ⌘N 新开；同一个文件夹可以同时开多个会话；从一个会话开出的会话列在它下面 |
| 模型等 | 模型、权限模式在开始时选，中途也能改 |

## 二、Consilium 现在哪里不对

1. **工作区靠猜或手打**：从消息里抓路径、在输入框里手输路径、在侧边栏里点了再改。Claude Code 是开始前从列表里选，或者在系统窗口里点选。
2. **会话不连续**：同一个会诊的追问会落到 Claude 的待命会话里，和其他会诊混在一起。Claude Code 是一个对话对应一个会话，上下文是连续的。
3. **“新开会话处理”要手动勾选**：本来就应该是默认行为。
4. **标题取消息开头前 40 个字**，不能点击改名。
5. **侧边栏没按文件夹分组**；“关闭会诊”的说法和 Claude Code 的“归档”不一样；会话做完时也不通知你。

## 三、改成什么样

1. **开始时选文件夹**：新会诊时，输入框下面一行是“📁 文件夹 ▾”和“发给：自动 / Claude / Codex / Antigravity”。
   - 文件夹菜单列出最近用过的文件夹，最后一项是“打开文件夹…”，会弹出 macOS 的选择窗口，窗口里可以新建文件夹。
   - 默认沿用上次选的文件夹。也可以选“不指定”，适合只是聊天、不碰文件的情况。
   - 会诊开始后文件夹固定，显示在标题栏上；要换文件夹就开一个新会诊。
   - 删掉：从消息里猜路径、手动输入路径、在侧边栏里改工作区。
2. **一个会诊对应一个原生会话**：
   - **Claude**：会诊里第一条发给 Claude 的消息，由待命会话在那个文件夹里开一个专属的 Claude Code 会话，名字和会诊一样。之后的追问都转给这个会话，上下文连续。这个会话在你的 Claude 侧边栏里会列在待命会话下面。
   - **Codex**：第一次发给 Codex 时，Consilium 会打开一个已经定位到这个文件夹的新 Codex 会话，你按一次发送。之后的追问由 Codex 的待命会话转进去，前提是 Codex 支持在会话之间转发；如果不支持，就由它直接处理，这一点需要实测。
   - **Antigravity**：同 Codex，用复制提示词的方式。
   - 删掉“新开会话处理”这个开关，默认就这样做。
3. **命名**：发出第一条消息后，由协调者按内容起一个短标题，你的原生会话也用同一个名字。点击标题栏里的标题可以改名，改名会同步到原生会话。
4. **侧边栏**：
   - 上面保留“三端”总览，下面保留看板；
   - 会诊列表改为按文件夹分组；
   - “关闭会诊”改叫“归档”，归档的会诊收进“已归档”；
   - 会诊有了新回复、而你没在看这个会诊时，发一条系统通知。
5. **模型和档位**：新会诊时可以选“快 / 均衡 / 深度”。Claude 端新开会话时，会按这个档位设置模型和推理强度。Codex 和 Antigravity 的模型由它们自己的 App 决定，Consilium 只显示它们上报的模型。
6. **工作树**：先不做。Claude Code 里它也默认关闭；以后需要时，只在 Git 仓库里提供这个开关。

## 四、需要实现的部分

- **App（Swift）**：给网页加一个“选文件夹”的桥，调用系统的 `NSOpenPanel`（可选目录、可新建文件夹），把选中的路径传回页面；会诊有新回复时，用系统通知提醒。
- **后端**：会诊记下每一端绑定的原生会话；新增 `consilium_bind_session` 工具；文件夹只接受已存在的绝对路径；去掉从消息里猜路径；新增改名和归档接口。
- **技能**：待命端拿到任务后，会诊已绑定会话就转发给那个会话；没有绑定就新开一个会话、绑定，再交给它。
- **测试**：上面每一项都写回归测试；截图只截电脑端。

## 六、确认方案与实现结果（2026-11-20）

- **用户决策**：采用该方案；工作目录必须在发消息前通过目录选择器或最近列表明确指定，不允许在输入框手填路径。
- **因此**：文件夹必须指定，而且只能选，不能填。去掉“不指定”，去掉界面上所有手填路径的地方；只保留“最近用过”列表和“选择文件夹…”（App 内用系统 NSOpenPanel，可以新建文件夹）。
- **已实现**：
  - 文件夹菜单和“快 / 均衡 / 深度”档位；
  - 一个会诊对应一个原生会话：`consilium_bind_session`；追问时任务带上 `native_session`；第一次发给某一端时 `new_session=1`；
  - 点标题改名，改过之后协调者不能再覆盖；
  - 归档 / 取消归档；侧边栏按文件夹分组，“已归档”收起；
  - 你不在 Consilium 窗口时，有回复就发系统通知；
  - 不再从消息里猜路径。
- **验证**：99 项测试通过；App 重建，冒烟测试两种情况都通过；已替换“应用程序”里的 App；技能已同步到三端，并已通知 Claude 待命会话按新规则转发。
- **待用户实测**：在 App 里点“选择文件夹…”是否弹出系统窗口；Codex 的追问能否接到同一个会话里。

## 七、平台限制与调整（2026-11-20）

- **限制**：Claude 桌面版不允许由自动事件唤醒的那一轮（例如后台等待进程退出）开新会话，只能提出建议、等用户点“开始”。Claude 待命会话正是这样被唤醒的，所以没法为每个会诊自动开一个专属 Claude 会话。
- **用户同意的调整**：
  - 默认由待命会话直接处理。取任务时附上这个会诊之前的对话（`conversation`，按毫秒时间排序），追问能接上上下文，在用户选定的文件夹里工作。
  - 需要专属会话时，用户点标题栏的“在 Claude 里开专属会话”：在该文件夹新开一个同名 Claude Code 会话，用户按一次发送，新会话自己调用 `consilium_bind_session`；之后这个会诊的消息由待命会话转给它。
- **验证**：99 项测试通过；App 重建，冒烟测试通过，已替换；技能已同步三端，并已通知待命会话。

## 九、不串线与左侧归档（R020，2026-11-20）

- **问题反馈**：需要隔离 Consilium 发起的会诊与外部项目的总线调用；归档只收起 Consilium 侧显示、不动三端原生会话；将归档入口放在左侧列表中以符合交互习惯。
- **原因**：三端的连接和技能是全局装的，别的项目里的会话也能用这条总线建会诊（那条“门铃 r5”就是另一个 Claude 会话建的）。窗口原来不分来源全部列出；同一端的所有会话又共用一个收件箱，待命会话会把别的会话的回执确认掉。
- **改法**：
  - 会诊记录来源：`ui`（在 Consilium 窗口里发起）或 `peer`（某个会话自己建的）。窗口只列 `ui`；旧数据库升级时按“有没有使用者消息”分类。
  - `consilium_pickup_inbox` 增加 `scope`（all / consilium / other）和 `mission_id`。待命会话默认只取窗口里发起的会诊；自己建会诊的会话用 `mission_id` 收自己的回执。
  - 归档从右上角菜单挪到左侧：鼠标移到会诊上出现归档按钮。归档只改 Consilium 里的显示，不动任务、事件和三端里的会话。
- **验证**：106 项测试在两种环境变量模式下通过（新增 `tests/test_r020_regressions.py` 6 项）；无头浏览器实测：别的项目的会诊不在列表里，悬停出现归档按钮，点击后进“已归档”且不会误开会诊；App 重建、冒烟测试通过并已替换；本机那条“门铃 r5”已被归为 `peer`，不再显示。
- **遗留**：待命会话仍可能被别的项目的门铃叫醒一次，取不到东西后回去继续等；要彻底避免需要把门铃信号也按来源分开。

## 十一、档位自动（R023，2026-11-20）

- **用户诉求**：输入框旁提供自动档位切换与自动决策能力，并支持在已创建的会诊中动态调整。
- **限制**：Consilium 不调用模型，也不能从外面替三个 App 切换模型；一个会话的主模型由使用者在那个 App 里定。能做到的是让处理的会话自己判断难度，并用 App 自带的办法执行（例如交给更高 effort 的子代理）。
- **实现**：
  - 任务的 `model_tier` 新增 `auto`，窗口发出的消息默认用它；`mission_tier` 为空时取件返回 `auto`。
  - 各端按难度定“快 / 均衡 / 深度”，用 `tier_used`、`tier_reason` 回报；协调者提示词、三段待命提示词和技能都写明“自己定、照做、不让使用者选”。
  - 输入框的档位按钮多一项“自动”（默认），已有会诊里也显示；改了之后跟着会诊走，追问没说档位时沿用。
  - 回复头部和任务页显示实际档位，悬停显示是自动定的还是指定的，以及理由。
- **验证**：110 项测试；无头浏览器实测已有会诊里的档位按钮、菜单、改档后发追问、任务页里的档位和理由，无脚本报错。
- **未验证**：三个 App 里的会话是否真的按档位换了推理强度，只能看它们上报的模型和 effort；已经开着的待命会话是旧工具，报不了档位。

## 十二、待命空转与原账号名（R024、R025，2026-11-20）

- **待命空转（待命会话报告）**：R020 让取件按来源区分后，等待仍只看“有没有未确认事件”。别的项目留下的回执（不归待命会话取）会让 `wait` 每次立刻返回，待命约每 10 秒空跑一轮。
  - 修法：门铃计数文件增加窗口来源的计数（`ui_seq`、`ui_unacked`、`ui_queued`、`other_seq`）；`wait_for_doorbell`、`consilium wait --scope`、`consilium_wait(scope=...)` 按来源判断；标签以 standby 结尾时默认 `consilium`。旧格式的计数文件按“全部算窗口来源”处理，不会漏叫。
- **原账号名**：应用户要求，在窗口中显示 Codex 与 Antigravity 的原始账号名而非 A/B/C 代号。
  - Codex 的名字取自 `codex_accounts.json` 的 email；Antigravity 只有 `current_account.json` 里的当前账号可读，其余账号在成为当前账号时记下。
  - 名字单独存表 `quota_account_names`，只有 `list_quota_windows(reveal_names=True)`（窗口的 `/api/state`）会带上；MCP 工具返回和协调者提示词仍是代号，测试断言了这一点。
- **验证**：111 项测试；用本机真实 Cockpit 记录核对（只看是否为原名和数量）：Codex 5 个账号都有名字，Antigravity 3 个里当前的 1 个有名字，工具侧输出不含邮箱。
