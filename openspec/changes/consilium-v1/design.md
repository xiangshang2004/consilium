# Design: `consilium-v1`

## 1. Frozen v1 Protocol & Data Model

- **Peers & Branches**: `claude` (`claude/`), `chatgpt` (`codex/`), `antigravity` (`gemini/`).
- **Task State Machine & Attempt Fencing**: `queued -> claimed -> running -> done | failed | blocked | cancelled`. `pickup_inbox` increments `attempt_seq`, generates `attempt_id` (`A-<seq>-<hex>`), and records `claim_latency_ms`; `report_progress` and `complete_task` require the active `attempt_id` and reject stale/missing attempts. Background `_reaper_thread` (`ConsiliumDaemon.start()`) runs `release_stale_claims`: expired `claimed` tasks (default 15m) auto-requeue to `queued` (archiving the prior attempt into `attempt_history_json`, emitting `task_requeued` to `coordinator_peer`, and waking `assignee_peer`); expired `running` tasks (default 2h, heartbeat via `updated_at`) are **not** auto-requeued—instead they set `stale_at` (preserving `attempt_id`) and emit `task_stale` to both `coordinator_peer` and `assignee_peer` until coordinator/dashboard calls `requeue_task` (permitted only for `claimed | running | failed | blocked` on open missions).
- **Peers 5-State Indicator Model**: `list_peers` computes `standby` (active flock waiter lease), `working` (no waiter, `claimed + running > 0`, not stale), `online` (no waiter, `claimed + running == 0`, `last_seen_at` within `stale_seconds`), `offline` (no `last_seen_at` or idle `claimed + running == 0` with expired `last_seen_at`), and `stale` (`claimed + running > 0` with stale task or expired peer heartbeat).
- **Mission State Machine**: `active <-> ready_to_report -> completed | cancelled | failed`.
- **Events**: `task_assigned`, `progress`, `task_done`, `review_request`, `loop_guard_reached`, `task_stale`, `task_requeued`, `mission_closed`.
- **Write Envelope & Scoped Idempotency**:
  - SQLite table `idempotency_keys(client_request_id PRIMARY KEY, operation, caller_scope, request_hash, response_json, created_at)` ensures retries across all 7 write operations (`create_mission`, `dispatch_task`, `report_progress`, `complete_task`, `requeue_task`, `request_review`, `close_mission`) replay the cached result only when `operation`, `caller_scope` (`peer:<id>` for peer-scoped calls and stdio `--peer` `consilium_dispatch_task`, `"coordinator"` for HTTP `consilium_dispatch_task`, `"dashboard"` for UI writes), and SHA-256 `request_hash` all match; mismatches raise `ConflictError` (HTTP `409` / MCP `isError: true`).
  - All 7 write MCP tools (out of 11 total MCP tools) return `{"committed": true, "result": <domain_result>, "delivery": <delivery_or_summary>}` (retaining top-level domain keys for backward compatibility). Post-commit errors in `_safe_sync_peers_seq`, `_safe_ring_peer`, `_safe_record_event_delivery`, and `publish_state_update` are deduplicated into `delivery.warnings` (and `post_commit_warnings` on `pickup_inbox`) while preserving `committed: true` and `isError: false`.
  - Event delivery metadata captures `claim_latency_ms`, causal `wakeup_latency_ms` (`record_peer_wakeup_latency` stamps only the single newest qualifying unacked non-cold event with `event_id <= wake_seq`), and 3 independent cold-notification facts (`attempted`, `command_status`/`command_ok`/`command_returncode`, `peer_acked`).

## 2. Concurrency-Safe `.seq`, Atomic `.lease`, & `kqueue` Wakeup

- Every update to `signals/<peer>.seq` acquires an exclusive lock on `<rendezvous_dir>/.<peer>.seq.lock` (`threading.Lock` + `fcntl.flock(LOCK_EX)`), located outside `signals/` so deleting `signals/` does not rotate the lock inode.
- Inside the lock, `BusStore.sync_peer_seq` invokes `query_peer_seq_counts` inside a single SQLite `BEGIN; ... COMMIT;` snapshot for authoritative `(MAX(event_id), unacked_events, queued_tasks)` and `_write_seq_payload_locked` atomically writes temp + `fsync` + `os.replace` with bounded 10-attempt retry on `OSError(ENOENT | EINVAL)`. `_read_peer_seq_unlocked` reads `.seq` directly without creating `signals/`.
- `ConsiliumDaemon.start()` and `run_stdio_server()` rebuild all three peers' `.seq` files from SQLite on startup so `/tmp` cleanup never hides pending work.
- `_acquire_lease` creates `.tmp-<pid>-<tid>-<rand>` via `O_CREAT | O_EXCL`, acquires `flock(LOCK_EX | LOCK_NB)`, writes JSON + `fsync`, and atomically `os.replace`s to `.lease`.
- `_wait_via_kqueue` (with 10-attempt `OSError(ENOENT | EINVAL)` retry in `_open_kqueue_watch`) subscribes to `KQ_NOTE_WRITE | KQ_NOTE_EXTEND | KQ_NOTE_ATTRIB | KQ_NOTE_DELETE | KQ_NOTE_RENAME`, re-opens on delete/rename, and continues waiting on spurious wakeups. `wait_for_doorbell` / `consilium_wait` / `consilium wait` are strictly read-only (`auto_pickup=true` / `--pickup` are ignored with `auto_pickup_ignored: true` and `notice`).

## 3. Security, Tokens, and Atomic Installer

- HTTP endpoints accept only `Authorization: Bearer <token>` (plus session cookie on UI/API routes); `?token=` query auth is rejected with HTTP `401` (`consilium serve --help` documents Bearer-only auth). Antigravity MCP uses `url` + `headers: {"Authorization": "Bearer <token>"}`.
- `consilium rotate-token` validates targets, updates configured client configs first, and atomically swaps `<state_dir>/auth.token` last; mid-rotation failure raises `TokenRotationError` carrying `updated_targets`, `remaining_targets`, `server_token_rotated`, `backup_root`, and `rollback_instructions` (CLI prints JSON to stderr and exits `1`). `ConsiliumDaemon.get_auth_state()` detects `auth.token` change, increments `_token_version`, revokes all `SessionStore` and `LoginTicketStore` entries, and calls `EventHub.close_all()`.
- `scripts/install.py` runs in two phases and supports `--targets` (`claude_desktop`, `claude_code`, `codex`, `antigravity`, `launchd`, `all`) and `--skip-claude-desktop`: Phase 1 validates JSON/TOML configs (including quoted/dotted Codex duplicates), CLI executability, and refuses `--apply` while `Claude.app` runs only if `claude_desktop` is selected; Phase 2 writes atomically with timestamped backups, strips `CLAUDE_CONFIG_DIR` when invoking `claude`, and verifies `claude mcp` rollback via `claude mcp get consilium` and `.claude.json` equality check.

## 4. Offline Dashboard (`/ui`, `/api/state`, `/api/stream`)

- **Minimalist Conversation `/ui` & Quota Pool**: Served directly by `ConsiliumDaemon` (`consilium/dashboard.py`), 100% inline HTML/CSS/JS, zero external CDN. Features a retractable left `会诊列表` sidebar (collapsed by default on `<= 860px`), compact topbar + unclipped `.peer-subbar` 3-peer status & active-account quota capsules (`演示数据` and `N号` badges + opaque `--bg-elevated` click popover), centered conversation stream (`max-width: 720px`) with truthful `"最后上报于"` timing and `.timeline-fade` fold, read-only bottom handoff composer + `/` command palette (`Esc` close, verified `claude://code/new?q=` and `codex://new?prompt=` deep links only, zero hardcoded model lists), and closed-by-default 5-tab right drawer (`任务`, `工作树`, `账号池`, `产物`, `子 Agent`). Login modal instructs `127.0.0.1:<port>/ui` instead of `localhost`.
- **Multi-Account Quota Whitelist (Q4)**: `consilium/quota.py` reads only `~/.antigravity_cockpit/codex_accounts.json` (`id`, `email`, `plan_type`, `current_account_id`), `codex-quota-history-v1.sqlite`, and `platform-quota-history-v1.sqlite` (never opening encrypted vault/credential directories), hashing emails/IDs via SHA-256 (`_hash_account_ref`) and tagging `is_current` / `is_historical`. `BusStore.sync_peer_accounts` and `list_quota_windows` aggregate `min_remaining_percent` / `dispatch_recommended` solely for the active account (`active_account_id`, `active_account_alias`, `current_account_unknown`, `account_switch_suspected`), returning read-only `pool`, `pool_has_capacity`, `best_backup`, and `switch_hint`.
- **Socket Fallback & HTTP Hardening (P3-1..3)**: `resolve_socket_path` supports `CONSILIUM_SOCKET_FALLBACK_DIR`; `_is_valid_origin` and `_is_exact_daemon_origin` catch `ValueError` on non-numeric ports; `_send_json` sets `close_connection = True` for `status >= 400`.
- **Authentication & Tickets**: `POST /api/login` validates Bearer/body token and creates a random server-side entry in `SessionStore` (12h TTL, random `session_id`, random `csrf_token`, bound `token_version`), setting `Set-Cookie: consilium_session=<session_id>; HttpOnly; SameSite=Strict; Path=/`. `POST /api/ui-ticket` (Bearer-only) issues a 30s single-use `token_version`-bound ticket consumed by `GET /ui/auth?ticket=...` (used by `consilium ui`, which exits `1` printing fallback URL if `open` fails); stale/invalid tickets redirect `302` without `Set-Cookie`. `POST /api/logout` revokes the session and closes its SSE streams.
- **Security Headers & Cookie-Write CSRF**: All JSON, HTML, redirect (`/` and `/ui/auth`), `202 /mcp`, and SSE responses send `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, and `Cache-Control: no-store` (`no-cache, no-store` on SSE); `/ui` HTML sets `Content-Security-Policy` with `frame-ancestors 'none';`. Cookie-authenticated writes (`POST /api/missions/<mission_id>/close`, `POST /api/tasks/<task_id>/requeue`, and `POST /api/logout` with an active session cookie) enforce exact daemon `Origin` (`http`, exact host & port, no path/query/userinfo -> `403`), `Content-Type: application/json` (`415`), and matching `X-Consilium-CSRF` (`403`); Bearer requests bypass cookie-CSRF checks.
- **Realtime SSE & External Sync**: `EventHub` caps concurrent streams at `SSE_MAX_SUBSCRIBERS = 16` (`503` on 17th), sets a `10s` socket write timeout, linearizes `publish_state` and `snapshot_with_version` via `_publish_lock` to guarantee monotonic `state_version` (checked on both server output and frontend `lastStateVersion`), terminates streams on `token_version` or session revocation, and runs `compute_state_fingerprint` (stripping volatile `age_seconds`/`claim_age_seconds`) to push `update` (`reason="external_change"` or `"waiter_change"`) when stdio/CLI processes mutate state.
