# Proposal: `consilium-v1` — Production-Ready Tri-Desktop Bus & Live Dashboard

## Why

The `init-deskbell` MVP proved the core bus and `kqueue` doorbell across 18 unit tests and the isolated Level-A terminal demonstration (`13_Consilium/03_演示记录/demo_a_timeline.md`). However, R005 identified 7 P1 reliability/security gaps (default auto-pickup on wait, `.seq` locking/rebuild/delete recovery, token placement in URLs/argv, unhooked stale-claim/running reaper, write/delivery error coupling without idempotency keys, cold notification deep links and `SKILL.md` wording, and non-atomic installer writes), and daily usability requires a clear, offline-capable live dashboard (`/ui`) before onboarding real desktop apps.

## What Changes

1. **Freeze v1 Bus Contract (`specs/bus/spec.md`)**:
   - Canonical peers (`claude`, `chatgpt`, `antigravity`), branch prefixes (`claude/`, `codex/`, `gemini/`), task/mission state machines, `attempt_id` claim fencing + `attempt_history` archiving, and event kinds (`task_assigned`, `progress`, `task_done`, `review_request`, `loop_guard_reached`, `task_stale`, `task_requeued`, `mission_closed`).
   - Uniform write response envelope `{"committed": bool, "result": {...}, "delivery": {...}}` across all 7 write MCP tools (including `consilium_requeue_task`, out of 11 total MCP tools) with post-commit fault isolation (`delivery.warnings` while preserving `committed: true` and `isError: false`) and scoped `client_request_id` idempotency (`(operation, caller_scope, request_hash)` raising `ConflictError`/HTTP `409` on mismatch).
2. **Stage 1 & R010 Remediation (Reliability & Security Fixes)**:
   - Make `consilium_wait` and `consilium wait` strictly read-only (`auto_pickup` / `--pickup` ignored with `auto_pickup_ignored: true`, zero DB writes); protect `signals/<peer>.seq` with `<rendezvous_dir>/.<peer>.seq.lock` (`flock` outside `signals/`), single-snapshot `BEGIN...COMMIT` DB re-query, bounded `OSError(ENOENT|EINVAL)` retry, atomic `.lease` creation (`O_CREAT|O_EXCL` + `flock` + `os.replace`), startup `.seq` rebuild, kqueue `NOTE_DELETE|NOTE_RENAME` recovery, and `queued_tasks` pre-check.
   - Enforce Bearer-only HTTP auth (rejecting `?token=` with `401` and moving Antigravity MCP config to `Authorization: Bearer` headers); add `consilium rotate-token` with live token reload and structured `TokenRotationError` rollback reporting; enforce two-phase atomic `scripts/install.py` validation (`--targets`, `--skip-claude-desktop`, `Claude.app` running guard for `claude_desktop`, `claude mcp get` + `.claude.json` rollback verification, `--rendezvous-dir`, `CLAUDE_CONFIG_DIR` isolation).
   - Hook up background `_reaper_thread` (`claimed` timeout auto-requeues with `task_requeued`; `running` timeout sets `stale_at` and emits `task_stale` to coordinator and assignee awaiting `consilium_requeue_task`); require active `attempt_id` on `report_progress`/`complete_task`; fix `ColdDoorbell.build_deeplink` (`claude://code/new`, `codex://new?prompt=...&path=...`), 3-fact cold delivery (`attempted`, `command_status`/`command_ok`/`command_returncode`, `peer_acked`), `claim_latency_ms`, and `SKILL.md`; address R005 P2 & R008/R009 items (strict RPC validation, closed-mission `request_review` guard, isolated quota sync & `null` `dispatch_recommended`, `CONSILIUM_DISABLE_LOCAL_QUOTA_SYNC=1`, `CONSILIUM_RENDEZVOUS_DIR` precedence).
3. **Stage 2 & R010 Hardening (Consilium Live Dashboard — `specs/dashboard/spec.md`)**:
   - Serve an inline, zero-CDN dashboard at `http://127.0.0.1:<port>/ui` backed by `/api/state`, `/api/stream` (SSE capped at 16 subscribers, 10s write timeout, monotonic `state_version`, fingerprint-based `external_change`/`waiter_change` detection, auto-reconnect and 3s polling fallback), random `SessionStore` cookies (12h TTL, `HttpOnly; SameSite=Strict`), `token_version`-bound `/api/ui-ticket` + `/ui/auth` (`consilium ui`), exact `Origin` + `application/json` + `X-Consilium-CSRF` cookie-write protection (`403`/`415`), active SSE/session/ticket revocation on token rotation or `/api/logout`, and `nosniff` / `Referrer-Policy` / `Cache-Control` / `frame-ancestors 'none'` security headers.
   - Provide light/dark/system themes, three peer cards (5-state status lights `standby`/`working`/`online`/`offline`/`stale`, session/activity, quota bar with `"未知"` for missing data, `<20%` low-quota color, `演示数据` badge for `source="demo"`, task counts), mission list with 100% done green progress bars and round indicator dots, collapsible-empty kanban task board with `renderInline` and attempt/stale pills, reverse-chronological event timeline (`显示更多` fade/expand, `claim_latency_ms`, hot/cold 3-fact badges), Markdown `final_summary` rendering, and two double-confirmed actions (`close mission`, `requeue task`).
4. **Stages 3–6 (Gated Rollout)**:
   - Level-B real Claude/Codex project-scoped trials, Level-C installation with `consilium doctor` and per-app smoke checklist, daily-use templates/exports, and operational log/DB backup hygiene—each gated behind `★` review/user approval.

## Non-Goals

- Modifying live `~/.claude`, `~/.codex`, `~/.gemini`, or `~/Library/LaunchAgents` before `★` gates and explicit user approval.
- Spawning `codex exec` or external CLI wrapper windows in the background.
- Adding third-party Python pip packages or external frontend CDN dependencies.
- Implementing a macOS menu-bar icon app (deferred to v1.1 pending user approval of Swift/extra dependency).
